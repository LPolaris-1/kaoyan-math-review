# 错题准入契约

`history.json` 只允许纳入同时包含“具体题目/题干”与“对应解法、推导或判断过程”的原档案。
构建与校验都调用 `scripts/shared/data-lib.mjs` 的 `collectSourceEntries()` 和
`classifyAdmission()`，因此使用同一源集合。文件名或 tags 含「错题」不再单独决定纳入，
准入由正文结构门禁动态审计。完整正文证据优先于目录、basename 等 legacy 线索；后者只在
缺少完整正文结构时作为排除理由，不能压过完整正文证据。

## 判定顺序

1. Frontmatter `entry_type: wrong_question` → **纳入**。
2. Frontmatter `entry_type: knowledge` → **排除**。
3. 其他非空 `entry_type` → **人工待确认**。
4. 正文结构门禁优先：正文同时具备「具体题目」与「过程证据」→ **纳入**。
   - 具体题目证据：存在二级及以下标题（`##` 及更深）包含「题目、原题、题干、问题、命题、
     原式、题型、典型题」等标记，且对应段落内容非空；其中「题型、典型题」的对应内容还必须
     包含「已知、设、若、求、计算、证明、判断、选择、下列」等作答语义，或明确的数学表达。
   - 过程证据：题目之后的正文中，标题或正文包含「解答、解析、解法、解题、求解、推导、证明、
     步骤、过程、思路、答案、破题、构造、方法、分析、标准、Step、第一步、第二步、选项、
     判断、最终」等标记。标题标记命中后，其子树（直到下一个同级或更高级标题之前）中存在
     非空正文即算过程证据；仅有标题而无正文不算。
5. 缺少完整正文结构时，再按 legacy 线索排除：
   - 旧目录名 `方法/`、旧文件名前缀 `题型-` → **排除**。
   - 文件名明确为纯知识笔记（以 `推导`、`结论集` 或 `运算[和]变换的区别` 结尾）→ **排除**。
6. 其余文件缺少任一类证据 → **排除**。fail-closed：不因文件名或 tags 含「错题」而放宽，
   也不再返回“人工待确认”。

只含通用方法、性质、公式、定理、总结、示例验证或反例、没有完整具体题目的文档一律排除。
以上均为确定性结构门禁，不做自然语言 AI 判断。

人工待确认数量大于 0 时，`data:build` 与 `data:verify` 在任何写入或发布前失败。
已锁定的历史日期仍由 `history.json` 优先保留；本契约不修改 Ebbinghaus 状态机、SQLite
schema、认证或服务器配置。

## 动态审计

准入结果由 `npm run data:build` / `npm run data:verify` 对原档案实时执行的结构门禁决定，
不再维护静态快照数字；新增或修改的原档案仍需先满足 LaTeX 硬门禁。
